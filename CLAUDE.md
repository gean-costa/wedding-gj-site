## Project

Wedding website for Gean Costa & Juliana Silva (13 Nov 2027, Belém - PA). Must work well on both desktop and mobile. Built incrementally, one section at a time. The owner is a beginner in web development and communicates in Portuguese (pt-BR): reply in Portuguese and explain new commands/concepts step by step. All site copy is in pt-BR.

Planned v1 sections: home (names, date, countdown), Nossa história, Cerimônia e Recepção (done), Confirmação de presença (RSVP, needs a backend/database), Lista de presentes. Hosting target: Vercel; code lives in a public GitHub repo, so never commit secrets (use `.env.local`, which is gitignored).

## Commands

```bash
npm run dev     # dev server at http://localhost:3000
npm run lint    # ESLint (flat config, eslint.config.mjs)
npm run build   # production build; also runs TypeScript checks
```

There is no test suite yet.

Source files are UTF-8 without BOM and full of pt-BR accents: never rewrite them with Windows PowerShell 5.1 `Get-Content`/`Set-Content` (it reads them as ANSI and corrupts accents); use the editor tools.

On this Windows machine Node/Git were installed via winget; if `node`/`git` aren't found in a shell that predates the install, refresh PATH first:
`$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`

## Architecture

- Next.js 16 App Router with `src/` dir, TypeScript, Tailwind CSS v4 (CSS-first config: theme tokens live in `@theme` in `src/app/globals.css`, no `tailwind.config`). Path alias `@/*` → `src/*`.
- `next.config.ts` enables `cacheComponents` and `partialPrefetching`. Under Cache Components, reading the current time/random values during server render is an error: anything time-dependent (e.g. `src/components/Countdown.tsx`) reads `Date.now()` only inside `useEffect` in a Client Component, or must use `connection()` + `<Suspense>` / `'use cache'`. Check `node_modules/next/dist/docs/` before using unfamiliar APIs.
- `src/lib/wedding.ts` is the single source of truth for couple names, date (stored with explicit `-03:00` offset; Belém has no DST), and venue data, plus Google Maps URL helpers (no API key needed). Pages should read from it rather than hardcoding details.
- Pages: home (`src/app/page.tsx`, anchor sections `#inicio`, `#historia` (teaser), `#cerimonia`), `/nossa-historia` and `/confirmar-presenca`. Every page renders `SiteHeader` (client component: fixed `h-16` bar, links from `md` up, ☰ dropdown below) and offsets content with `pt-16`; anchor sections use `scroll-mt-16`. Nav links live in `SiteHeader.tsx` and use absolute paths (`/#cerimonia`) so they work from any page.
- Every page also renders `SiteFooter` after `</main>`: the couple's pets (data + SVG drawings in `src/components/Bichos.tsx`, `familia` array in age order, the dog Yoshi last; Pompom and Yoshi have passed away and wear a halo) drawn in the `contorno` style. Home uses `variante="azulejos"` (pets sitting on an `AzulejoBand`); other pages use the default `espiando` (heads + paws peeking over a `bg-primary` bar). Each pet shows its name in a CSS-only tooltip on hover/focus (`tabIndex` so a tap works on mobile). Sizes come from the `--w` CSS var per breakpoint so all 11 fit one row at 320px. Drawings support styles `chapado`/`contorno`/`aquarela`; patches/stripes go in `marcas`, clipped by the body via `<clipPath>` (clipPath children must be bare shapes, not `<g>`). `/estilos/rodape` is the comparison page.
- `/nossa-historia` tells the couple's story as a river boat journey whose ports are milestones, ending at the wedding. Its identity is inspired by "abridores de letras" (hand-painted lettering on Amazonian river boats), in the wedding palette: `CascoDeBarco` (hull header: stripes, lettering, ornament, waterline waves into a `bg-river` section) + `LetraDeBarco` sign lettering modeled on the layered "Muita Onda" font family (Sancreek Tuscan font, uppercase; stacked text layers: two-tone split fill with sparkle pattern, thin dark outline, 3D extrusion going up-right; `shallow` prop shortens the extrusion for small text) + `Floreio` ornament. Timeline entries ("portos") are data in `src/lib/historia.ts` (placeholder text until the couple sends real dates/stories), icons in `HistoriaIcon.tsx`; the last port (the wedding) is derived from `wedding.ts`. This identity belongs to Nossa história only.
- `/confirmar-presenca` (RSVP) has its own identity: a sealed airmail letter. The form sits inside an airmail-striped letter addressed to the couple, with postage stamps (`SeloPostal`, modeled on the 1978 Correios Theatro da Paz stamp) and a postmark (`Carimbo`) in the corner; more stamps flank the letter on `xl` screens (mirrored rotations) and form a grid below it on smaller ones (2 cols, 3 from `sm`). Stamps are rendered by the client component `SelosTrocando.tsx`: 8 fixed slots (0-1 on the letter, 2-7 around it) with a uniform 4:3 art window and `SeloPostal uniforme` (title-only caption, fixed 2-line height); every 7.5s one visible letter slot (0, or 1; slot 0 only from `sm`) swaps with one random outside slot (2-7): both fade out, swap landmarks and fade back (skipped under `prefers-reduced-motion`). Slots own size and rotation, so swapping never changes the layout. Stamps show Belém landmarks drawn in SVG from real photos in `src/components/BelemIlustracoes.tsx` (Ver-o-Peso, Theatro da Paz, Basílica de Nazaré, Estação das Docas, Relógio, Forte do Presépio, Casa das Onze Janelas, Mercado de São Brás); each drawing supports variants `linha`/`silhueta`/`aquarela`/`selo` (the page uses `selo`). Do not bring the river-boat identity to this page. `RsvpForm` (no card of its own) does NOT persist anything yet: on submit it only shows a thank-you message client-side; storage/backend is still to be decided.
- Theme: wedding palette tokens `ink` #575C60, `primary` #667588, `secondary` #98AEC3 (low contrast on light bg: decoration only, not small text), `stone` #898788, `mist` #D9D9D9, `paper` #F6F7F9, plus aliases `background`/`foreground`/`accent`, all in `@theme` in `globals.css`. Fonts `font-sans` (Geist), `font-serif` (Playfair Display, placeholder pending choice), `font-script` (Italianno, for the couple's names), wired via CSS variables from `next/font` in `src/app/layout.tsx`. Names are always shown bride first ("Juliana & Gean") and must fit on one line (hero uses `whitespace-nowrap` + `clamp()` font size).
- Visual identity is Portuguese azulejos (Belém's Cidade Velha). Tile designs are inline SVG on a 100x100 grid in `src/components/AzulejoDesigns.tsx`, each drawn so motifs continue into the neighboring tile when repeated. Designs have no grout; `withJoint(Tile)` adds the grout joint + glaze edge (`TileJoint`). The site uses `TileFlorComRejunte` (Flor simples with grout; petals in #BFDDF3); `TileArabesco`, `TileInstituto`, `TileOctogono` are kept on purpose for future use. `/estilos/azulejo-novo` shows every design with and without grout. `src/components/Azulejo.tsx` wraps them as `AzulejoBackground` (SVG `<pattern>`; `id` must be unique per page), `AzulejoGrid`, `AzulejoBand`, `AzulejoIcon`, `AzulejoFrame`, all defaulting to Flor simples with grout and accepting an optional `Tile` prop.
- Home hero snaps to the tile grid: CSS vars `--tile`/`--cols`/`--rows` per breakpoint; `AzulejoGrid` draws the grid anchored at its parent's top-left with tile size from `--tile`; the wall height `--h` is `round(down, 100svh - 4rem, var(--tile))` and the card's top margin is rounded to whole tiles, so the wall's top/bottom edges and all four card edges land on grout lines (section `border-y` completes the half-joint at the wall edges).
- `src/app/estilos/**` are temporary comparison pages used to make design decisions with the couple (styles, azulejo usage, fonts, tile catalog). Not linked from the site; remove before publishing.
- Visual checks without a browser: headless Edge screenshots (`msedge --headless=new --screenshot=... --window-size=W,H URL`). Headless can't render below ~500px wide, so for mobile widths screenshot a local HTML file containing `<iframe>`s of 375px/320px pointing at localhost.
